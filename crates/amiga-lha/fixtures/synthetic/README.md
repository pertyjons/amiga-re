# Synthetic LHA payloads

These are compressed payloads, without archive headers. No private media or
third-party assets are included. Tests assemble headers and compare the complete
recovered bytes with the synthetic patterns below. No encoder is built or run
by the test suite, and the former `testing` feature has been removed.

## Static methods

`lh45-*` uses four-bit offset-table fields (`-lh4-` / `-lh5-`); `lh67-*`
uses five-bit fields (`-lh6-` / `-lh7-`). These fixtures were assembled on
2026-09-11 from explicit single-symbol blocks, using the framing in delharc
0.8.0 [`src/decode/lhv2.rs`](https://github.com/royaltm/rust-delharc/blob/ea1d90f1febb75e3aa9b53c45f170127074a0fba/src/decode/lhv2.rs).
They do not use the removed static test encoder.

A block consists of these fields, most-significant bit first:

| Field | Bits | Value |
| --- | --- | --- |
| Command count | 16 | As specified below |
| Temporary tree count, single symbol | 5 each | 0, 0 (unused) |
| Command tree count, single symbol | 9 each | 0, command |
| Offset tree count, single symbol | 4 or 5 each | 0, offset symbol |
| Match offset suffix | offset symbol minus 1 | Only for matches with offset symbol greater than 1 |

Concatenate blocks without byte alignment; zero-pad only the last byte.
A command below 256 repeats that literal `count` times. A match command is
`256 + length - 3`; its offset symbol is the bit length of `distance - 1`.
For offset symbols greater than 1, the suffix is `distance - 1` minus the
highest set bit. The fixtures use these blocks:

- `literals`: one count-1 literal block for each byte of
  `SYNTHETIC ARCHIVE TEST PAYLOAD -- a member worth compressing`.
- `overlap`: count-1 literals `A`, `B`, `C`, then a length-6, distance-3 match.
- `repeat`: one literal `Z`, then a length-16, distance-1 match.
- `boundary`: a count-8190 literal `Z` block, then a length-16, distance-1 match.
- `spaces`: one literal `A`, then a length-4, distance-64 match into the initial
  dictionary. Delharc initializes that dictionary with spaces.
- `wide`: 300 count-1 literals with values `index % 251`, then a length-20,
  distance-300 match.
- `ring`: for each byte value 0 through 255, one count-300 literal block,
  then a length-20, distance-300 match. This wraps every supported dictionary.
- `hunk`: count-1 literals for these ten big-endian u32 words:
  `0x3f3, 0, 1, 0, 0, 1, 0x3e9, 1, 0x4e714e75, 0x3f2`.

On 2026-09-11, 7-Zip 26.02 recovered the exact expected bytes for all 26
static fixture/method combinations other than `spaces`. Verification wrapped
each payload in a level-0 member named `x`, with matching lengths and CRC-16,
and compared `7z x -so` output with the expected bytes. The installed 7-Zip
rejects initial-dictionary references and does not implement `-lh1-`; it is
not an oracle for those cases. Delharc verifies those against the explicit
expected bytes in `tests/decoding.rs`.

## Adaptive method and negative sample

The four `lh1-*` payloads are fixed outputs of the former
`testing::adaptive::encode` at repository revision `6440070`, captured before
removing that encoder. They contain only these supplied synthetic symbols:

- `literals`: 300 literals, each `index % 251`.
- `overlap`: literals `a`, `b`, `c`, then a length-6, distance-3 match.
- `spaces`: one length-4, distance-8 match.
- `rebuild`: 200,000 literals, each `index % 7`, exercising adaptive tree rebuilds.

The encoder's historical references remain unknown; its source is no longer
part of the current tree. These generated payloads contain no encoder source.
They check delharc against stated byte patterns, not an independently established
conformance corpus.

`incomplete-legacy-lh5.bin` is a negative sample generated by the old static
`testing::encoder::encode` at the same revision, with `[Literal(b'A')]`,
offset-count width 4 and dictionary width 13. The old `FlatCode` assigned
uniform code lengths without adding its claimed padding leaves. It produced
incomplete trees that the old decoder accepted. Delharc rejects this sample;
its only valid test expectation is a malformed-stream error. Its SHA-256 is
`3565a8320a233d2ea1867591d4527b7fda4bf5dca1abfee7b3b9b06ff05f2067`.
